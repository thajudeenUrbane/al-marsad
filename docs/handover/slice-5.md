# Slice 5 handover: connect outward (external ID candidates)

Spec: docs/handover/slice-5-brief.md. Every row written is a proposal for scholars (`status = proposed`). Nothing merges, splits or edits an entity; identity.csv is untouched; no ID was typed by hand: each external_id is copied from a response received (cached in build/cache/link_external/, gitignored, 29 MB). IDs are current after slice 1e.

## What exists
- `ontology/tools/link_external.py`: reads identity.csv and the Turtle files build_graph.py loads; writes the three CSVs below. Wikidata through query.wikidata.org/sparql only (MWAPI entity and full-text search batched with VALUES, then labels, aliases, descriptions, dates, coordinates, P13870 and family links; at most one request starts per second, five at most in flight, backoff on 429/timeouts). al-Thurayya `master/places.geojson`; OpenITI author metadata (kitab-metadata-automation) plus Wikidata P13870. `--offline` reads the cache only, `--check` (offline) exits 1 if a CSV differs, `--report` lists ties, exclusions and uncovered entities. The docstring states every rule.
- `ontology/corpus/external-ids.csv` (256 rows): canonical_id, kind, system, external_id (QID, al-Thurayya URI, OpenITI URI), external_label (English / Arabic as the source gives it), evidence (which of our fields matched what, and how), confidence, status.
- `ontology/corpus/external-coordinates.csv` (69 rows): the coordinates each place candidate carries, exactly as its source gives them, with the source, the distance to the corpus's own (proposed) point, and the link's confidence. For the map, use exact/probable rows only.
- `ontology/corpus/external-dates.csv` (328 rows, 139 people; coordinator's request for the lifelines view): every birth/death statement of every person candidate on Wikidata, not deprecated: value as given, precision, calendar model, match confidence, rank, qualifiers (age at event, refine date such as "74 AH", circa, earliest/latest date) and a note. A year-precision value (0610-01-01T00:00:00Z) means the year. The query service converts day-precise Julian dates to Gregorian; for those 21 rows the value is the one Wikidata stores (Special:EntityData) and the note gives the converted one. Draw lines from exact/probable rows (133 people).

## How confidence is decided (details in the tool's docstring)
Names are compared after one normalisation (diacritics, ʿ ʾ, al-/as-, ibn/bin/b./bint, Abdullah/ʿAbd Allāh, final -ah); a consonant comparison (Tayyihan/Tayyahan, Warqa/Verka) only ever gives needs-review. A name alone is never `exact`. People: `exact` needs an equal full name (3+ words, or fewer with a family link or our death date), no equally supported rival, nothing contradicting (gender, our death date), and one more agreement: our death date, a family link (our spouse/parent/child/sibling matched to an item this one names as family), or a dated life in 500–950 CE plus a description of the period. Anyone the corpus puts at an event or records as a ṣaḥābī cannot match an item born after 640 or dead after 740 (this removed a 3rd-century Abū Khaythama). Places: `exact` needs the English or Arabic name and a point within 15 km of the corpus's own; `probable` within 50 km or, without a point of ours, a name unique in al-Thurayya (a classical gazetteer) with a same-name Wikidata item beside it. Buildings, events and items >100 km from our point are left out. OpenITI follows the exact/probable Wikidata candidate; `exact` only when both directions agree.

## RDF: CSV only
marsad.ttl has the right container, `mrs:Assertion` with `mrs:assertionStatus mrs:as_proposed`, but `mrs:predicate` must name a `mrs:RelationType` from relations.ttl and the registry has none for "aligned with an external record"; `mrs:externalIdentifier` sits on the entity itself with no status, so using it would state the link as fact. Adding a relation type is an ontology change outside this slice. Suggested: add one (e.g. `mrs:rel_aligned_with`); each CSV row then becomes an Assertion (subject the entity, object the external IRI, status proposed, `nonReportBasis` the evidence, `prov:wasGeneratedBy` a run of this tool), and only an accepted one becomes `mrs:externalIdentifier`.
