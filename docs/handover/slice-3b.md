# Slice 3b handover — review pages for phone and laptop

Spec: docs/handover/slice-3-brief.md, part 3b. No status moved in the real corpus and nothing was invented: the test reviewer, citations and notes say they are fixtures, and every test works on a temporary copy.

## What exists (review/)
- `build_pages.py` rebuilds `review/dist/queue.json` (3a), then writes `review/dist/` (gitignored): `index.html`, one page per batch (`story-01.html`, `person-<id>.html`, ...) and `sw.js`. `--queue FILE` uses an existing queue; `--scope "<roster scope>"` builds only what one scholar may decide (3a's scope syntax). Today: 97 batch pages, the heaviest 94 KB (the Prophet ﷺ's first 50 claims; story 21: 93 KB). Deterministic.
- Each page is one self-contained file: style and script inlined from `static/review.css` and `static/review.js`, no request anywhere. Text from `i18n/en.json` via `templates/`; logical CSS only. The card controls are written once (`<template>`) and copied into each card by the script.
- A card: the claim as the queue words it; status, file, topic, period, ID; "basis is an AI-generated document" and "cite to accept" flags; the source beside it (60 rem and up) or below it (phones): the document's wording, the basis, each passage (a story page shows the story once at the top, and folded in each card). Arabic in `lang="ar" dir="rtl"` wherever the queue has it: today only 9 names and the Thawr report's matn, which the graph holds as "…". Accept / Reject / Needs discussion are 56 px tiles; the four checks are tick boxes; the citation field is required to accept wherever `citation_required_to_accept` is set; the note is required for Needs discussion. Identity questions ("same as?") get the same card.
- Keyboard: 1–4 tick checks; A, R, D decide, then the next claim opens (or the field still needed); C, N go to the fields; J, K move; Enter in the citation moves on; Esc leaves a field; X clears; S goes to Send.
- The reviewer enters their opaque ID once (or opens a link ending `#reviewer=agt:…`, then taps Save). It and every decision live in localStorage, per ID and claim, saved on each change; all access is in try/catch, with a memory fallback and a visible warning when the browser will not keep them. No name is asked for or written anywhere.
- **Send my decisions**: ONE file in 3a's schema (`format`, `version`, `reviewer_id`, `created`, `queue` fingerprint, `decisions`) with every finished decision on the device for that ID. Unfinished ones are listed with links and held back. It goes to the share sheet when the browser can share the file (as `.json`, else `.txt`: Android Chrome shares `.txt` but not `.json`), otherwise it downloads `.json`; "Save as a file instead" always downloads. Sending again is safe (the importer skips what it has). A decision changed after sending is flagged (a change goes through the maintainer, 3a rule).
- Offline: once a page is loaded nothing needs the network. Over https or localhost, `sw.js` keeps each opened page (network first), so it reopens without a connection.

## Maintainer's steps
1. On your machine only: copy `review/roster.example.csv` to `review/roster.csv` (gitignored). One row per scholar: `reviewer_id` from `.venv/bin/python ontology/tools/mint_id.py agt`, name, role `scholar`, scope (e.g. `source:stories-50`), granted_on, granted_by.
2. Build: `.venv/bin/python review/build_pages.py` (for one scholar: add `--scope "<their scope>" --out <folder>`).
3. Send each scholar their link or file. Link: put `review/dist` on any https static host (or, to try it, `python -m http.server -d review/dist`) and send `…/index.html#reviewer=<their ID>`. File: send the batch page(s) and their ID over WhatsApp.
4. Receive their decision file over WhatsApp (or email) and save it in `review/inbox/`. A phone's `.txt` holds the same JSON: rename it to `.json` (the importer reads `inbox/*.json`) or pass it by name.
5. Run `.venv/bin/python review/import_decisions.py --dry-run`, then without `--dry-run`. It prints the roster name for each file: check it is the sender. Then rebuild (`ontology/build_graph.py`, `site/build.py`, `review/build_pages.py`): decided claims leave the queue.
