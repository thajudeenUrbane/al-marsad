# Slice 4 handover: AI-assisted ingestion of Ibn Hishām's Sīra

**Source.** OpenITI `0213IbnHisham.SiraNabawiyya.Shamela0023833-ara1` (primary version), the file at commit 2cfdc8cf of github.com/OpenITI/0225AH, sha256 8e0d274c…99cd. Base edition as the file's metadata names it: al-Saqqā, al-Abyārī and Shalabī, 2nd ed., Cairo 1375/1955, **PROVISIONAL** (E33). Page numbers are that edition's as OpenITI marks them; nobody has checked them against print.

**Licence finding.** OpenITI releases are CC BY-NC-SA 4.0 (Zenodo releases 2025.1.9 and the primary-version release). The GitHub repo has no licence file, and the text comes from al-Shamela. NonCommercial cannot go into CC BY-SA 4.0, so **the text is not committed**:
- `ingest/cache/` is gitignored. `python ingest/ibn_hisham.py fetch` downloads the file at the pinned commit and checks its sha256.
- What is committed: offsets, checksums, names, ascriptions and chains as written, and short age and date expressions. Each report's `mrs:matnText` is a notice, not the matn.
- Maintainer: please confirm that quoting names and these short expressions is acceptable. LICENSING.md does not yet mention this source; I did not edit it because it is out of scope.

**What exists.**
- `ingest/ibn_hisham.py` (`fetch | build | check | review | locate`) rebuilds `ontology/corpus/ibn-hisham.ttl` byte for byte from the cache plus `ingest/claims/*.jsonl` (no Arabic in the JSONL files).
- Entities are resolved by name through identity.csv. No IDs are hard-coded, so a rebuild picks up renames. The build refuses any ID retired in id-renames.csv.
- The model: Work (Ibn Isḥāq) → Recension (Ibn Hishām) → Edition → Witness (with an SPDX checksum) → Passage, which records page, milestone, lines and characters.
- Each passage has one Report. The ascription is kept as written ("qāla Ibn Isḥāq") and never completed.
- 10 chains with 23 links are modelled. Where a chain ends in unnamed narrators it is not modelled, and the passage note says why.
- Each claim is an Assertion with fromReport, an `oa:TextPositionSelector` span, status `proposed`, coverage `stub`, and an AI gloss labelled as machine-written. Each is generated by the agent "AI extraction pass (slice 4)" on 2026-10-15. No model is named anywhere.
- `review` writes `ingest/cache/review.html` (local only) showing every claim beside its Arabic span.

**Numbers.**
- 106 reports and **404 claims**. Report ascriptions: 69 qāla Ibn Isḥāq or similar, 23 with no formula, 12 mawqūf, 2 maqṭūʿ.
- Claims by predicate: participated_in 177, sheltered 38, spouse_of 24, migrated_to 22, sibling_of 22, travelled_via 22, **age_at 20**, **died_during 16**, **dated 11**, father_of 11, mawla_of 11, absent_from 4, **born_during 3**, mother_of 3. Two each: adopted_by, ally_of, ancestor_of, cousin_of, **died_at**, manumitted, paternal_uncle_of, sheltered_at. One each: fought_against, migrated_from, occurred_at, preceded.
- Qualifiers: hedged 7, text_alternative 5, share_not_present 3, editorial_brackets 1.
- **Lifelines:** 52 claims, from every birth, death and age statement in the chosen passages. Ages are kept as written (`mrs:ageAsWritten`), plus the numbers the text gives (`mrs:ageYearsAsGiven`, one value per alternative, e.g. 7 and 8). No passage states a calendar basis, so none is recorded. Nothing is computed or converted.
- **Entities:** 180 new (136 people, 25 places, 19 events), with identity.csv rows appended at the end (needs-review, Arabic name as in the text). 79 existing entities are referenced. Nobody was merged or split.

**New vocabulary (needed for lifelines).**
- relations.ttl: `rel_born_during`, `rel_died_during`, `rel_age_at`, and `rel_dated` (its object is the time expression as written).
- marsad.ttl: `mrs:ageAsWritten`, `mrs:ageYearsAsGiven`, `mrs:dateAsWritten`.
- shapes.ttl: `AgeAndDateAssertionShape`, which requires an age on an age claim and a literal object on `rel_dated`.

**Spot-check.** 20 claims, seeded random sample (seed 20261015): A4a.1, A7.2, A11.1, C6.8, C6.10, C6.17, C9.1, H13.1, H13.2, H14.11, E2.4, E5.5, E6.5, E8.2, E11.1, B4.1, B6.1, B7.11, B12.3, B12b.1. All 20 match their spans. Some glosses carry context from the wider passage, not from the span itself (H13.2, H14.11).

**Needs a scholar (judgement calls, each also in the passage notes or identity rows).**
- Identifications made on context: al-Zuhrī → Ibn Shihāb; Khārija b. Zayd → "Kharijah ibn Zayd"; Ṣuhayb b. Sinān → "Suhayb al-Rumi" (on the strength of Ibn Hishām's note); the mabʿath at forty → "The first revelation, at Ghar Hira'"; A18, Abū Bakr's "fī mithli sinnihi" linked to the arrival at Qubāʾ.
- Kept apart on purpose: ʿAbdullāh b. Abī Bakr b. Ḥazm is not Abū Bakr's son; Khabbāb, mawlā of ʿUtba, is not Khabbāb b. al-Aratt; the Muʾta event is not the stories-50 one.
- ʿĀʾisha's ages at marriage and at the Prophet's death are sensitive and need scholarly review. The direction of mawlā links needs confirming.
- Ascriptions are left uncompleted: the lodging of ʿUmar's group, Abū Ḥudhayfa's host, and the bare "qāla" in C5.
- **The Prophet's age at his death is not stated in the passages read** (I searched). His death is dated only by the day (a Monday) and the time of day.
- Bilāl "muwallad of Banū Jumaḥ" (B13b) is a birth-status statement with no fitting predicate, so it is not claimed. A27 "in my turn" is not treated as a date.
- Abū Bakr now has his name as this text writes it (C4). Without it, searching "أبو بكر" ranked Asmāʾ bint Abī Bakr above him.

**For a human.**
1. **identity_audit.py does not know this file.** The one line for its `FILES` dict is:
   `"ibn-hisham": ROOT / "ontology" / "corpus" / "ibn-hisham.ttl",  # slice 4, generated by ingest/ibn_hisham.py`
   With that line the audit reports 79 `source_files` mismatches, all of one kind: the existing rows this file references need `;ibn-hisham` added. I did not change existing rows.
2. `scripts/check_all.sh` passes except one step, `site/observatory: tests`: `test_transmission_frame_shows_only_recorded_chains` fails with 25 != 28. The observatory merges repeated narrator pairs into one link, and three pairs recur across reports: al-Zuhrī→Ibn Isḥāq and both links of the Yaḥyā b. ʿAbbād chain. The data is right; the test should count distinct pairs.
3. `site/model.py` assumes every `assertionObject` is an IRI. On the 11 `rel_dated` claims, rdflib warns "does not look like a valid URI". Site tests pass, but the site should learn literal objects.
